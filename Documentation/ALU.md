# ALU (Arithmetic Logic Unit)

## Overview
The **ALU** is the computational core of the single-cycle RISC-V processor. It performs all arithmetic, logical, shift, and comparison operations required to execute RISC-V instructions. The operation to perform is selected using a 4-bit control signal (`con`), which is typically generated by the ALU Control unit based on the instruction's `funct3`, `funct7`, and opcode fields.

This module is purely **combinational** — all outputs are derived instantaneously from the current inputs with no clock or internal state retained across cycles.

---

## Module Declaration

```verilog
module ALU #(parameter N = 32) (
    input  [N-1:0] A,
    input  [N-1:0] B,
    input  [3:0]   con,
    output reg [N-1:0] res,
    output zero,
    output reg carry,
    output reg overflow,
    output negative
);
```

## Parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `N` | 32 | Data width of the ALU operands and result. Parameterized to support easy retargeting (e.g., RV64 in the future). |

## Ports

| Port | Direction | Width | Description |
|------|-----------|-------|-------------|
| `A` | Input | `N` bits | First operand (typically `rs1` or PC, depending on operation). |
| `B` | Input | `N` bits | Second operand (typically `rs2` or an immediate value). |
| `con` | Input | 4 bits | ALU control/opcode selector — determines which operation is performed. |
| `res` | Output (reg) | `N` bits | Result of the selected ALU operation. |
| `zero` | Output (wire) | 1 bit | Asserted when `res == 0`. Used for branch equality checks (`BEQ`, `BNE`). |
| `carry` | Output (reg) | 1 bit | Carry-out from addition/subtraction. |
| `overflow` | Output (reg) | 1 bit | Signed overflow flag for addition/subtraction. |
| `negative` | Output (wire) | 1 bit | Sign bit of the result (`res[N-1]`), indicating a negative result in two's-complement form. |

## Internal Signals

| Signal | Width | Purpose |
|--------|-------|---------|
| `temp` | `N+1` bits | Extra-wide accumulator used during ADD/SUB to capture the carry-out bit beyond the normal result width. |

## Operation Table (`con` decoding)

| `con` (binary) | Mnemonic | Operation | Result Expression |
|-----------------|----------|-----------|--------------------|
| `4'b0000` | ADD | Addition | `res = A + B` |
| `4'b0001` | SUB | Subtraction | `res = A - B` |
| `4'b0010` | AND | Bitwise AND | `res = A & B` |
| `4'b0011` | OR | Bitwise OR | `res = A \| B` |
| `4'b0100` | XOR | Bitwise XOR | `res = A ^ B` |
| `4'b0101` | SLT | Set Less Than (signed) | `res = ($signed(A) < $signed(B)) ? 1 : 0` |
| `4'b0110` | SLTU | Set Less Than (unsigned) | `res = (A < B) ? 1 : 0` |
| `4'b0111` | LUI | Load Upper Immediate | `res = {B[31:12], 12'b0}` |
| `4'b1000` | AUIPC | Add Upper Immediate to PC | `res = A + {B[31:12], 12'b0}` |
| `4'b1001` | MOVE | Pass-through of B | `res = B` |
| `4'b1010` | SLL | Shift Left Logical | `res = A << B[4:0]` |
| `4'b1011` | SRA | Shift Right Arithmetic (signed) | `res = $signed(A) >>> B[4:0]` |
| `4'b1100` | SRL | Shift Right Logical | `res = A >> B[4:0]` |
| default | — | Undefined operation | `res = 0` |

## Behavioral Details

### Default Assignments
At the start of every combinational evaluation, `res`, `carry`, and `overflow` are reset to `0`. This is a **critical safety practice** — without these defaults, the outputs could infer unintended latches in synthesis, since not every branch of the `case` statement explicitly drives all outputs (e.g., logical operations like AND/OR don't touch `carry`/`overflow`).

### ADD (`4'b0000`)
- Computes `A + B` using a `(N+1)`-bit intermediate (`temp`) to catch the carry-out bit.
- `carry = temp[N]` — the bit beyond the normal result width, representing unsigned overflow.
- `overflow` (signed) is computed using the classic rule: **overflow occurs when both operands have the same sign, but the result's sign differs from theirs.**
  ```verilog
  overflow = (A[N-1]==B[N-1]) && (res[N-1]!=A[N-1]);
  ```

### SUB (`4'b0001`)
- Computes `A - B`, similarly using `temp` for carry/borrow detection.
- Signed overflow rule for subtraction: **overflow occurs when the operands have different signs, and the result's sign differs from A's sign.**
  ```verilog
  overflow = (A[N-1]!=B[N-1]) && (res[N-1]!=A[N-1]);
  ```

### Logical Operations (AND / OR / XOR)
Straightforward bitwise operations with no carry/overflow semantics — these remain at their default `0` values.

### SLT / SLTU (Set Less Than)
- `SLT` performs a **signed** comparison via `$signed()` casts, correctly handling negative numbers in two's complement.
- `SLTU` performs a **raw unsigned** comparison, treating both operands as unsigned magnitudes — critical for instructions like `SLTU`/`SLTIU`.

### LUI (Load Upper Immediate)
- Ignores `A` entirely; places the upper 20 bits of `B` (the immediate) into the top of the result, zero-filling the lower 12 bits.

### AUIPC (Add Upper Immediate to PC)
- Adds the upper-immediate-formatted value of `B` to `A` (where `A` is expected to be the current PC). This is used to compute PC-relative addresses.

### MOVE
- Simple pass-through of `B` to `res`. Useful for instructions where the ALU is used merely as a conduit (e.g., certain pseudo-ops or `JAL`/`JALR` link-value handling, depending on datapath design).

### Shift Operations (SLL / SRA / SRL)
- Only the lower 5 bits of `B` (`B[4:0]`) are used as the shift amount, since a 32-bit shift range only requires 5 bits (0–31).
- `SLL`: logical left shift (zero-fill).
- `SRL`: logical right shift (zero-fill from the top).
- `SRA`: arithmetic right shift, using `$signed(A)` so the sign bit is replicated (sign-extended) during the shift — correct behavior for signed right shifts.

### Default Case
Any unrecognized `con` value results in `res = 0`, providing a safe fallback and preventing undefined behavior/latches.

## Output Flag Logic (Continuous Assignments)

```verilog
assign zero = (res == 0);
assign negative = res[N-1];
```

- **`zero`**: Combinationally derived from `res` regardless of which operation produced it. This is essential for branch instructions (`BEQ` uses `zero` after a SUB operation to detect equality; `BNE` uses `~zero`).
- **`negative`**: Simply the MSB of the result, representing the sign bit in two's-complement representation. Can be used for signed branch comparisons (`BLT`, `BGE`) in some datapath designs.

---

## Design Notes & Observations

- **Combinational-only design**: No clock, no registers holding state — output is purely a function of current inputs, appropriate for a single-cycle datapath where the ALU result must be ready within the same clock cycle.
- **Carry/Overflow only meaningful for ADD/SUB**: For all other operations, these flags default to `0` and should be ignored by downstream logic.
- **Parameterization (`N`)**: While currently used for RV32 (`N=32`), the shift amount width (`B[4:0]`, 5 bits) and immediate slicing (`B[31:12]`) are hardcoded for 32-bit operation. Extending this ALU to RV64 would require updating these constants (shift amount would need 6 bits for a 64-bit datapath).
- **LUI/AUIPC hardcoded bit-widths**: The `{B[31:12], 12'b0}` slicing assumes a 32-bit-wide immediate field layout and would need adjustment if `N` changes.
- **`con` encoding gap**: Only 13 of the 16 possible 4-bit codes are used (`0000`–`1100`); `1101`–`1111` fall to `default`, leaving room for future operation additions.

## Usage in the Datapath

The ALU sits in the **Execute (EX)** stage of the single-cycle datapath. Its inputs typically come from:
- `A` ← Register file output (`rs1`), or PC (for `AUIPC`).
- `B` ← Register file output (`rs2`), or sign/zero-extended immediate (selected via an ALU input mux, `ALUSrc`).

Its outputs feed into:
- `res` → Data memory address (for loads/stores), write-back data (for R-type/I-type), or PC calculation.
- `zero` → Branch comparator/control logic for conditional branches.
- `negative`/`carry`/`overflow` → Optional use in more advanced branch condition logic (e.g., `BLT`/`BGE` if not handled via SLT).
