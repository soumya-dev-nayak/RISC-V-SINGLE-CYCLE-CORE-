# `WriteBack_MUX.v` — Register Writeback Select Mux

## Overview
`WriteBack_MUX` is the final mux in the datapath before a result is written back to the register file. It selects which computed value — the **ALU result**, **data memory read output**, or **PC+4** (link address) — actually gets written to the destination register `rd`, based on the `ResultSrc` control signal generated by `MainDecoder.v`.

This module also incorporates a **defensive bug fix**: an explicit case for `ResultSrc = 2'b11` was added instead of relying on an implicit `default`, closing off a class of silent-zero-writeback bugs.

---

## Module Interface

### Parameter
| Parameter | Default | Description |
|-----------|---------|--------------|
| `N` | 32 | Data width in bits |

### Inputs
| Signal | Width | Description |
|--------|-------|--------------|
| `ALU_result` | 32 | Output of the ALU |
| `Mem_data` | 32 | Data read from `Data_Memory.v` (for loads) |
| `PC_plus4` | 32 | `PC + 4`, the link address (for JAL/JALR) |
| `ResultSrc` | 2 bits | Selects which of the above is written back |

### Output
| Signal | Width | Description |
|--------|-------|--------------|
| `Result` | 32 | Value ultimately written to the register file (`rd`) |

---

## `ResultSrc` Encoding

| `ResultSrc` | Selected `Result` | Used By |
|:---:|---|---|
| `00` | `ALU_result` | R-type, I-type ALU ops, LUI, AUIPC |
| `01` | `Mem_data` | Loads (`lw`, `lh`, `lb`, ...) |
| `10` | `PC_plus4` | JAL, JALR (link address) |
| `11` | `ALU_result` (fallback) | Reserved / currently unused |

---

## Key Design Notes

### The `2'b11` Fix
The header comment flags a specific, deliberate correction: previously, the `case` statement likely relied on Verilog's **implicit default behavior** for the unhandled `2'b11` encoding, which — depending on synthesis/simulation semantics — could resolve to `0` (or an unknown/latched value) rather than a sensible fallback. That's a **silent bug**: if any future instruction, decoder change, or encoding drift ever produced `ResultSrc = 2'b11`, the register file would quietly get written with `0` (or `X`) instead of a meaningful value, with no warning.

The fix adds an **explicit** `2'b11: Result = ALU_result;` case, so if this encoding is ever reached, it degrades gracefully to the ALU result — the least surprising fallback — rather than silently zeroing a register.

### Currently Unused, Kept for Safety
Per the header comment, once `MainDecoder.v` was fixed so that **LUI** uses `ResultSrc = 2'b00` (not `2'b11`), no instruction in the current decoder actually drives `ResultSrc = 2'b11`. The explicit case is retained anyway as **defensive completeness** — a form of future-proofing against decoder changes, encoding typos, or new instructions being added later without every downstream mux being re-audited.

### Fully Combinational, Latch-Free
The `case` statement covers **all four** possible values of the 2-bit `ResultSrc` (`00`, `01`, `10`, `11`) explicitly, with `Result` declared as `reg` and assigned in every branch — this guarantees no latch is inferred, since every possible input combination has a defined output.

## Relationship to Other Modules
- **`MainDecoder.v`** — generates `ResultSrc` based on the current instruction's opcode.
- **`ALU.v`** — supplies `ALU_result`.
- **`Data_Memory.v`** — supplies `Mem_data` (the loaded word, for `lw`-type instructions).
- **`PC_Plus_4.v`** — supplies `PC_plus4` (used as the link address for JAL/JALR).
- **`Register_Set.v`** — receives this module's `Result` output as the value to write into `rd` when `RegWrite` is asserted.
