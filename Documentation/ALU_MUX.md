# ALU Input MUX (ALU_MUX)

## Overview
The **ALU Input MUX** is a simple 2:1 multiplexer that selects the second ALU operand (`SrcB`) between the register file's `rs2` value and the sign/zero-extended immediate value produced by the Immediate Generator. This selection is controlled by the `ALUSrc` signal from the Main Control unit, and is a standard structural element in RISC-V datapaths that allows a single ALU to serve both register-register (R-type) and register-immediate (I-type, S-type, U-type, etc.) instruction formats.

This module is **purely combinational**, implemented as a single continuous assignment.

---

## Module Declaration

```verilog
module ALU_MUX #(parameter N = 32)
(
    input  [N-1:0] rs2_data,   // from register file
    input  [N-1:0] imm,        // from immediate generator
    input          ALUSrc,     // control signal
    output [N-1:0] SrcB        // to ALU
);
```

## Parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `N` | 32 | Data width of the operands, matching the processor's word size (RV32). |

## Ports

| Port | Direction | Width | Description |
|------|-----------|-------|--------------|
| `rs2_data` | Input | `N` bits | The second source register value read from the Register File (`rs2`). |
| `imm` | Input | `N` bits | The immediate value produced by the Immediate Generator, already sign/zero-extended to `N` bits. |
| `ALUSrc` | Input | 1 bit | Control signal from the Main Control unit selecting the ALU's second operand source. |
| `SrcB` | Output (wire) | `N` bits | The selected value routed to the ALU's `B` input. |

---

## Behavioral Logic

```verilog
assign SrcB = (ALUSrc) ? imm : rs2_data;
```

| `ALUSrc` | `SrcB` Selected | Typical Instruction Types |
|----------|------------------|----------------------------|
| `0` | `rs2_data` | R-type instructions (`ADD`, `SUB`, `AND`, `OR`, `SLL`, etc.) and branches (`BEQ`, `BNE`, etc.), where the ALU compares/operates on two register values. |
| `1` | `imm` | I-type (`ADDI`, loads, `JALR`), S-type (stores), U-type (`LUI`, `AUIPC`) — where the ALU's second operand must come from the instruction's immediate field. |

---

## Design Notes & Observations

- **Ternary-based mux**: Implemented as a single-line continuous assignment using the ternary operator — the simplest and most synthesis-friendly way to express a 2:1 mux in Verilog, mapping directly to a hardware multiplexer.
- **No internal state**: Purely combinational; output changes instantaneously with any change in `rs2_data`, `imm`, or `ALUSrc`.
- **Control signal origin**: `ALUSrc` is generated by the Main Control unit as part of the decoded control signal set (alongside `ALUop`, `RegWrite`, `MemWrite`, etc.), based on the instruction's opcode.
- **Parameterized width (`N`)**: Like the ALU, this module is parameterized for reusability, though currently used at the default RV32 width of 32 bits.
- **Placement in datapath**: This mux sits immediately before the ALU's `B` input, forming the second half of ALU operand selection (the first operand, `A`, is typically either `rs1_data` or the PC, depending on instruction type — often handled by a separate mux not shown here).

---

## Usage in the Datapath

```
Register File ──→ rs2_data ──┐
                              ├─→ [ALU_MUX] ──→ SrcB ──→ ALU (input B)
Immediate Gen ──→ imm ────────┘
                     ▲
                     │
              ALUSrc (from Main Control)
```

This module allows the same ALU hardware to be reused across nearly all instruction types by simply toggling whether the second operand comes from a register or from the decoded immediate — a key simplification enabling the single-cycle datapath's uniform ALU-centric execution path.
